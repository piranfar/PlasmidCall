# PlasmidCall v1.1: input specification

This page lists the exact inputs of `plasmidcall_v1_1_m2.pkl` and how they are built. The
reference is the frozen scorer, `scripts/evaluation/v11_scorer_p111.py` (`build_features`,
`score_frame`, `score`, and the `score` mode of `main`). `scripts/score/plasmidcall_score.py`
follows the same steps and reproduces the frozen P1.13 v1.1 scores exactly.

## Per-contig inputs

| Input | Frozen column name | Meaning |
|---|---|---|
| 12 tool calls | `HyAsP` ... `plASgraph2` | one of `chromosome`, `plasmid`, `unknown`, `unclassified`, `repeat`, `FAILED`, `MISSING` |
| contig length | `SR contig length` | length of the contig in bp |
| contig count | `Number of SR contigs` | number of contigs of at least 1 kb in the contig's sample (see below) |

The tool order is HyAsP, MOB-recon, PLASMe, PlaScope, Plasmer, PlasmidEC, PlasmidFinder,
Platon, RFPlasmid, geNomad, gplas2, plASgraph2.

## Step 1: recoding FAILED and MISSING

`FAILED` and `MISSING` are recoded to `unknown` before any feature is built. They are then
abstentions, like `unknown`, `unclassified` and `repeat`. A failed or absent tool is never
turned into a chromosome vote.

## Step 2: features

The pipeline builds 51 columns: 29 from the calls and 22 numeric.

**Calls (one-hot, 29 columns).** Each tool is one-hot encoded with the categories seen in
training. A category not in this table sets no column for that tool (`handle_unknown="ignore"`).
For example, `unknown` for HyAsP sets no HyAsP column.

| Tool | Categories |
|---|---|
| HyAsP, MOB-recon, Plasmer, PlasmidEC, PlasmidFinder, Platon, RFPlasmid, geNomad | `chromosome`, `plasmid` |
| PLASMe | `chromosome`, `plasmid`, `unknown` |
| PlaScope | `chromosome`, `plasmid`, `unclassified` |
| gplas2 | `chromosome`, `plasmid`, `repeat`, `unknown` |
| plASgraph2 | `chromosome`, `plasmid`, `unknown` |

**Numeric (22 columns), in this order.** Counts are taken after step 1.

| Feature | Definition |
|---|---|
| `n_valid` | number of tools whose call is not `unknown`, `unclassified` or `repeat` |
| `n_plasmid`, `n_chrom` | number of `plasmid` and `chromosome` calls |
| `n_abstain` | 12 - `n_valid` |
| `frac_plasmid`, `frac_chrom` | `n_plasmid` / `n_valid` and `n_chrom` / `n_valid`; missing when `n_valid` = 0 |
| `agreement` | max(`frac_plasmid`, `frac_chrom`) |
| `SR contig length` | contig length in bp |
| `log10_len` | log10(max(length, 1)) |
| `log10_nsr` | log10(max(contig count, 1)) |
| `abst_<tool>` (12) | 1 when that tool's call is `unknown`, `unclassified` or `repeat`, else 0 |

The numeric features go through a median imputer and a standard scaler fitted in training. When
no tool votes chromosome or plasmid (`n_valid` = 0), the three fractions are missing and the
imputer fills them with the training medians: `frac_plasmid` 0.0, `frac_chrom` 1.0,
`agreement` 1.0. v1.2-General sets them to 0.0 instead.

`n_valid` counts every value outside the abstention set. With calls limited to the seven
states, `n_valid` = `n_plasmid` + `n_chrom`. The scorer refuses any other value.

## The contig count

**Definition.** The number of contigs of at least 1,000 bp in the same sample. When the table
has no `Number of SR contigs` column, the frozen scorer counts, per sample, the rows of the input
table whose length is at least 1,000 bp (`v11_scorer_p111.py`, `score` mode). The P1.10
evaluation used the same rule (`scripts/model/evaluate_model1_p110.py`), and
`docs/evidence/P1.9C4_model1_independent_validation_2026-08-19.md` records it. In training, the
value came from the `Number of SR contigs` column of the development bundle.

**Warning.** Because the count is taken from the table, the input table must contain every
contig of at least 1 kb of each sample. Contigs shorter than 1 kb do not change the count. A
table that holds only some contigs of a sample gives a smaller count and different scores. To
score a subset, give the count per row in an `n_contigs_ge_1kb` column; the scorer then uses it
and checks that it is the same for every row of a sample and not smaller than the number of
contigs of at least 1 kb in the table.

**Size of the effect.** On the public P1.13 frozen prediction table (19,320 contigs, 150
samples):

* counting every contig instead of only those of at least 1 kb changes the v1.1 call of 932
  contigs;
* scoring a table that holds only the 695 resistance-gene-bearing contigs, so that the count
  comes from those rows, changes 95 of their 695 calls.

Both numbers come from `python tests/test_plasmidcall_score.py --p113-table
P1.13_FROZEN_PREDICTIONS.tsv`, which asserts them.

**No contig of at least 1 kb.** For a sample without one, the count is undefined and v1.1
abstains (`model_abstain`) on every contig of that sample. An `n_contigs_ge_1kb` value of 0 is
treated the same way.

## Contig length

A length that is missing or not a number makes v1.1 abstain on that contig, and the contig is
not counted. v1.1 returns a score for contigs of any length. The P1.11 and P1.13 evaluations
counted only contigs of at least 1 kb, so scores for shorter contigs were never evaluated.

## Domain

v1.1 was fitted only on contigs that the development bundle flagged as carrying a resistance
gene. In the router it is applied only to contigs with a qualifying AMRFinderPlus determinant
(element type AMR, subtype AMR, scope core, class not EFFLUX). Scores on other contigs are
outside its training domain.

## Output

| Score | Call |
|---|---|
| at least 0.9605 | `high_confidence_plasmid` |
| at least 0.9524 and below 0.9605 | `plasmid_selected` |
| below 0.9524 | `not_selected` (no positive plasmid evidence, never a chromosome call) |
| not computable | `model_abstain` |

## Environment

scikit-learn 1.9.0 exactly, numpy 2 or later, and pandas. See `models/README.md` for the reason
and for the pickle safety note.
