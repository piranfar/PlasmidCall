# P1.9 — Classification benchmark discovery

**Date:** 2026-08-16
**Phase:** discovery and protocol design only. No dataset was downloaded or imported.
**Objective:** find or design a benchmark able to test the actual Model 1 task — assigning
short-read assembly contigs to *plasmid*, *chromosome*, *mobile/plasmid-like but
chromosomal*, or *ambiguous/shared/unmapped*, with explicit confidence.

Primary success target is unchanged: **PPV ≥ 95% with recall > 50%** (strong success
recall ≥ 60%), with confidence intervals clustered at isolate or genome-cluster level.

---

## 1. Headline findings

**1. The most relevant public benchmark is already in use.** The strongest candidate the
search surfaced — *Circling in on plasmids* (Briefings in Bioinformatics 2025,
doi:10.1093/bib/bbaf589), supporting repository `broadinstitute/plasmid-detection-benchmark` —
turns out to be the **Teixeira dataset this project already uses**. `data/predictions.xlsx`
in that repository has git blob id `b49b0c5b9ec0fee13da168737fa713e307e6b1f8`; the local
Teixeira file has the identical blob id and sha256 `db558a67…2646e091`. `CONFIRMED`.

This resolves a standing ambiguity: the project's "12-tool ensemble" is the twelve plasmid
**detection** tools benchmarked in that paper — HyAsP, MOB-suite, gplas2, PLASMe, PlaScope,
Plasmer, PlasmidEC, PlasmidFinder, Platon, RFPlasmid, geNomad, plASgraph2. It also means
that dataset **cannot serve as independent validation** of any model fitted on it.

**2. A genuinely suitable public benchmark exists, and it is the only one with graphs and a
four-class truth.** `fmfi-compbio/plasgraph2-datasets` supplies, per assembly, a gzipped
**GFA assembly graph** and a per-contig CSV labelling every contig `chromosome`, `plasmid`,
`ambiguous`, or `unlabeled`. `CONFIRMED` by direct inspection of the repository tree, its
README and its sample catalogue.

**3. No public candidate supplies a deliberate mobile-chromosomal hard-negative layer.**
That is precisely the sequence class that dominates current Model 1 false positives. It has
to be constructed.

## 2. What the two usable public datasets actually contain

### 2.1 `plasgraph2-datasets` — verified, not inferred

| Property | Verified value |
|---|---|
| Samples | **436** (`all_samples.csv`, 436 distinct `our_id`) |
| Assemblies | **872** — every sample assembled twice, SKESA (`-s`) and Unicycler (`-u`) |
| Files | 872 `*.gfa.gz` + 883 `*.csv` (1,756 blobs total) |
| Species | **53 distinct** |
| Labelled contigs | 38,110 (ESKAPEE test) + 39,007 (non-ESKAPEE), contigs > 100 bp |
| Truth classes | `chromosome`, `plasmid`, **`ambiguous`**, **`unlabeled`** |
| Per-contig columns | `contig`, `label`, `length`, `chrom_score`, `plasmid_score` |
| Coverage | present in GFA — `dp` tag (Unicycler) or `KC` tag (SKESA) |
| Short reads | SRA accession for **436/436** samples |
| Long reads | accession for **436/436** samples (Nanopore or PacBio) |
| Chromosome references | `reference_genomes.csv` |
| Licence | **NOT DOCUMENTED** — no LICENSE file; GitHub licence field is null |

Subsets: `eskapee-train` 70 (10 per ESKAPEE species), `eskapee-test` 112, `cfre-test` 50,
`efer-test` 50, `koxy-test` 31, `bacillus-test` 34, `cjej-test` 30, `myco-test` 30,
`sent-test` 29.

Truth construction, quoted from the source paper (Frontiers in Microbiology 2023,
doi:10.3389/fmicb.2023.1267695): hybrid assemblies label contigs > 1 Mbp as chromosome and
shorter circular contigs as plasmid; `minimap2` homology mapping then labels contigs > 1,000 bp
as plasmid if they map to the plasmid database over ≥ 80% of their length and to the closed
reference over ≤ 20%, and as chromosome under the converse rule; a contig matching both
equally well is labelled **`ambiguous`**. The README states plainly that `ambiguous` means
the contig "should be correctly classified as both a chromosome and a plasmid (e.g. a
transposon present in both molecules)".

That definition matters: it is a *shared-sequence* class, not a *mobile-chromosomal* class.
A transposon present on both molecules is labelled ambiguous, but an IS element or
integrated plasmid segment present **only** on the chromosome is labelled `chromosome` and
is exactly the hard negative Model 1 keeps mis-calling. The dataset contains such contigs
but does not flag them, so the hard-negative layer must still be derived.

**Why it is not yet `READY`:**

- **Licence NOT DOCUMENTED.** Reuse and redistribution terms are undeclared. The underlying
  reads are public NCBI/ENA/DDBJ accessions, but the derived graphs and labels carry no
  stated terms.
- **Overlap with the PlasEval E. coli set is `CANNOT DETERMINE`.** It contains 18 *E. coli*
  samples; P1.8B used 53 *E. coli* isolates from Zenodo 13117709, both traceable to the
  same author group. An accession-level cross-check is required before any evaluation.
- **Provenance clustering is mandatory.** Samples derive from 16 source studies, dominated
  by Shaw2021 (152) and Robertson2018 (120, the MOB-suite corpus), with 10 from
  ArredondoAlonso2018 (mlplasmids). Same-study and near-identical-plasmid clustering must
  precede any split.
- **No DOI-backed archive and no published checksums.** GitHub only, last pushed 2023-08-30.

### 2.2 `plasmid-detection-benchmark` — already in use

250 genomes (93 Enterobacterales across 14 species and 6 genera; 157 Enterococcus across 17
species). Truth by `nucmer` (MUMmer 3.23) alignment of short-read contigs to matched hybrid
assemblies; contigs mapping equally well to chromosome and plasmid were **excluded**, and
contigs < 1,000 bp were excluded. Both binary detection (12 tools) and reconstruction
(4 tools) were evaluated.

Two consequences for this project:

1. It **cannot** be an independent test set for Model 1 — Model 1 was fitted and evaluated
   on it. `CONFIRMED`.
2. Its ambiguity rule *discards* equally-mapping contigs rather than labelling them. Our
   four-class target therefore cannot be recovered from it, and its reported precision and
   recall are computed on a truth set from which the hardest cases were removed.

Independently, the paper reports **gplas2** as the highest-scoring reconstruction tool and
among the highest-scoring detection tools. Our P1.8B-R2 result — species-specific gplasCC
significantly outperforming gplas2 on reconstruction in *E. coli* — is consistent with and
extends that finding.

## 3. Does any dataset provide explicit binary truth?

**Yes — three do, with different limitations.**

| Dataset | Binary chromosome/plasmid truth | Usable as independent Model 1 test set |
|---|---|---|
| `plasgraph2-datasets` | **YES**, plus `ambiguous` and `unlabeled` | **YES**, subject to the licence and overlap gates |
| `plasmid-detection-benchmark` | **YES** (ambiguous contigs excluded) | **NO** — already used to fit and evaluate Model 1 |
| PlasEval Zenodo 13117709 | **NO** — positive-only plasmid bins | **NO** |
| mlplasmids | binary by construction; packaged label table **NOT LOCATED** | `CANNOT DETERMINE` |
| Platon / Plasmer / PlasmidEC | `CANNOT DETERMINE` | `CANNOT DETERMINE` |

So the answer to "is there a public binary-truth benchmark for this task" is yes — and the
practical difficulty is not scarcity but **independence**: the best-matched corpus is
already inside Model 1's own development loop.

## 4. Search completeness

Eleven receipts are recorded in `P1.9_search_receipts.tsv` (nine successful, one partial,
one failed retrieval — bioRxiv returned HTTP 403).

**This search is NOT exhaustive and must not be described as such.** No recall audit was
performed, and five of the eleven receipts return `UNKNOWN` total hit counts because the
search interface does not expose them. Under `PROJECT_GOVERNANCE.md` §7 that bars an
exhaustiveness claim. Equally, `PROJECT_GOVERNANCE.md` §11 bars the opposite error: nothing
here supports a claim of data scarcity, because two usable corpora were found in a single
pass.

Verification depth differs by candidate and is recorded per row in
`P1.9_candidate_benchmarks.csv`. Only C01, C02 and C03 were verified by direct inspection of
files. C04–C07 are `PARTIAL`, `CANNOT DETERMINE` or `UNSUITABLE` on the evidence gathered,
and the label "not located" means exactly that — not "does not exist".

## 5. Gaps that remain open

1. **Licence for `plasgraph2-datasets`** — `NOT DOCUMENTED`. Blocks reuse until resolved.
2. **PlasEval ↔ plasgraph2 *E. coli* overlap** — `CANNOT DETERMINE`. Requires an
   accession-level cross-check.
3. **mlplasmids labelled-contig table** — `NOT LOCATED`, recoverable in principle from ENA
   PRJEB28495 plus the figshare long reads.
4. **PlasmidEC and Plasmer corpora** — `CANNOT DETERMINE`; not examined in this pass.
5. **No public mobile-chromosomal hard-negative layer exists** in any candidate.
6. **Species coverage for gplasCC** — plasmidCC ships species-specific databases for only
   some of the 53 species in C01; which of them are covered is `NOT DETERMINED`.

---

## 6. Recommendation

See `P1.9_decision_gate.md`. In summary: **HYBRID_BENCHMARK_RECOMMENDED** — pursue
`plasgraph2-datasets` as the external benchmark behind two explicit gates, and build the
controlled benchmark specified in `P1.9_controlled_benchmark_protocol_draft.yaml` from the
project's own complete genomes, because only the controlled route can supply the
mobile-chromosomal hard negatives that dominate current Model 1 errors.
