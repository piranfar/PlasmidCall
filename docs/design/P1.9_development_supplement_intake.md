# Development supplement — intake and validation hook

**Date:** 2026-08-17 · **Stage:** P1.9B part K · **Status:** hook created, **not executed**

The single artifact that unblocks the independence audit is the article's supplementary
tables workbook. It cannot be retrieved programmatically: PMC serves a JavaScript
proof-of-work challenge to non-browser clients and OUP returns 403. Neither is circumvented.

---

## What the owner does

1. Open the article in an ordinary browser — PMC `PMC12602193` or the OUP page for
   doi:10.1093/bib/bbaf589. The browser satisfies the challenge automatically, as it does
   for any reader.
2. Download **`Circling_in_on_plasmids_-_Supplementary_Tables_bbaf589.xlsx`** (~3 MB).
3. Place it, unrenamed, in the intake directory:

```
<local>\AppData\Local\Temp\claude\E--Github-Project-amr-evidence-warehouse\38c5e1c2-5b1f-426e-844a-9665518b3e5d\scratchpad\p19b\intake\
```

Do not overwrite anything already there — the hook refuses to overwrite and will say so.

## Command to run once the file is present

```bash
python "<local>\amr-evidence-warehouse\scripts\p1_9\inspect_development_supplement.py" --intake "<local>\AppData\Local\Temp\claude\E--Github-Project-amr-evidence-warehouse\38c5e1c2-5b1f-426e-844a-9665518b3e5d\scratchpad\p19b\intake"
```

It is read-only with respect to the Warehouse. Until the file exists it prints
`NOT PRESENT` and exits without doing anything.

## What the hook checks, in order

| # | Check | Failure behaviour |
|---|---|---|
| 1 | File present | prints `NOT PRESENT`, exits 2 |
| 2 | **Is it really a workbook** — `PK` magic, not HTML | `REJECTED_NOT_A_WORKBOOK`, exit 3. This specifically catches the bot-protection interstitial, which arrives with an `.xlsx` filename |
| 3 | Bytes, MD5, SHA-256 recorded | always recorded |
| 4 | **ZIP safety** — no absolute or `..` member paths, compression ratio ≤ 200, uncompressed ≤ 500 MB | `REJECTED_UNSAFE_ARCHIVE`, exit 4 |
| 5 | Sheet inventory — names, row and column counts, headers | recorded |
| 6 | **Identify Supplementary Table 1** by the highest count of accession-like header fields | `TABLE_S1_NOT_IDENTIFIED`, exit 6 |
| 7 | **Require exactly 250 development sample mappings** | discrepancy is **reported**, never silently reconciled |
| 8 | Refuse to overwrite an existing proposed crosswalk | `REFUSED_WOULD_OVERWRITE`, exit 7 |

## What it produces

- `P1.9_development_accession_crosswalk_PROPOSED.csv` — every value copied **verbatim** from
  the sheet, with `source_sheet`, `source_row`, a `mapping_status`
  (`EXACT_ACCESSION_MAPPING` / `AMBIGUOUS_MAPPING` / `NOT_DOCUMENTED`) and `inferred: NO` on
  every row.
- `P1.9_supplement_inspection_receipt.json` — hashes, sheet inventory, identification basis,
  row-count reconciliation, decision.

**No accession is ever guessed.** Rows that are ambiguous or incomplete are preserved with
that status rather than dropped or filled in. **No canonical Warehouse record is written** —
`canonical_records_written: 0` — and the crosswalk is a *proposal* pending owner approval.

## What happens next

On approval, `docs/evidence/P1.9_development_accession_crosswalk.csv` is superseded by a new
version (append-only supersession, the original retained), and the Part D audit re-runs. Every
`IDENTIFIER_INCOMPLETE` verdict is then replaced by a real one, and the primary cohorts can
move off `PENDING_INDEPENDENCE`.
