### Copyright holder and scope

- **Copyright holder:** not stated in any examined artifact. The repository is owned by the
  `fmfi-compbio` organisation (Faculty of Mathematics, Physics and Informatics, Comenius
  University Bratislava), and the paper's authors are the presumptive rights holders.
  Asserting a specific holder would go beyond the evidence: `CANNOT DETERMINE`.
- **Scope covered by an explicit grant:** none — code, metadata, GFA graphs, label CSVs,
  derived benchmark tables, redistribution and publication of derived metrics are **all
  undocumented**.

### Reasoning

No licence was inferred from the software repository, and none from the article's own CC-BY
terms: a Frontiers open-access licence covers the **article**, not a third-party code or data
repository it merely points to. Absence of a licence is not permission — under GitHub's terms
of service, publishing a repository without a licence grants only the right to view and fork
**within GitHub**, and reserves all other rights.

Nor is absence peculiar to this group's practice: sibling `fmfi-compbio` repositories do
carry licences (Apache-2.0, MIT), so the omission here is best read as an oversight rather
than an implicit dedication to the public domain. Either way the operative status is the same.

### What this does and does not block

**Blocks:** downloading, redistributing or republishing the repository's derived artifacts —
the 872 GFA graphs and 872 label CSVs.

**Does not block:** the route the paper itself documents. The underlying data are public
GenBank/SRA records, and `all_samples.csv` supplies short-read and long-read accessions for
**436 of 436** samples. The labelling procedure is fully specified in the paper —
`minimap2` homology mapping, plasmid ≥ 80% of contig length with ≤ 20% to the closed
reference, chromosome under the converse rule, equal matches labelled `ambiguous`. An
independent rebuild from primary accessions is therefore scientifically and legally clean.

Reading small files through the GitHub API to verify schema, and reading `all_samples.csv`
(51,093 bytes, a sample catalogue), is inspection rather than redistribution. No graph, read
set or bulk label corpus was downloaded.

**Authors were not contacted, as instructed.**

### Label schema — verified from source, not inferred

One label file was read to confirm the schema
(`cjej-test/campylobacter_cjej-SAMD00491660-u.gfa.csv`, 1,331 bytes, the smallest in the
repository):

```
contig,plasmid_score,chrom_score,label,length,chr_coverage,pl_coverage,un_coverage,hybrid_mapsto
1,0,1,chromosome,591634,591634,0,0,1
```

**Allowed label values, confirmed against the README's normative statement:**
`plasmid` · `chromosome` · `ambiguous` · `unlabeled`.
Observed in the probe file: `chromosome` 22, `plasmid` 1, `unlabeled` 17 of 40 contigs.
**No class was normalised or merged.**

The README defines `ambiguous` as a contig that "should be correctly classified as both a
chromosome and a plasmid (e.g. a transposon present in both molecules of the given sample)",
and `unlabeled` as truth unknown, typically short contigs.

**Material finding beyond the documented schema:** the label files carry four columns the
README does not mention — `chr_coverage`, `pl_coverage`, `un_coverage` and `hybrid_mapsto`.
These record the per-contig alignment evidence behind each label and the hybrid contig it
maps to. That is more than a label: it is the raw material for deriving a
**mobile-chromosomal hard-negative stratum**, which P1.9 requires and which no candidate was
expected to supply. A chromosomal contig with non-trivial `pl_coverage` is precisely the
plasmid-like chromosomal sequence that dominates current Model 1 false positives.
