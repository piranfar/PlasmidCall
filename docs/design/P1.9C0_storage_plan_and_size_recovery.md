## 1. Correction to the previous estimate

P1.9B.1 reported tier sizes as `UNMEASURED_FALLBACK`. The cause is now identified and fixed:

**ENA's `filereport` endpoint accepts only ONE accession per call.** My earlier batched call
passed comma-separated accessions and received a header row with **zero data rows**, which the
script recorded as "0 runs sized" and silently fell back to literature-typical values.

Demonstrated:

| Call | Result |
|---|---|
| `accession=SRR2014925` | `fastq_bytes 89857785;104438930` — **works** |
| `accession=SRR2014925,SRR3112258` | header only, **no rows** — the earlier bug |

**All 524 runs across the 262-sample Tier-3 population are now measured individually.**
Four initial failures (`SRR2171006`, `SRR12298624`, `DRR065947`, `DRR161275`) were transient
and resolved on retry. **0 unresolved.**

The fallback overstated sizes by roughly 1.3–1.5×. Real per-sample median is **1.034 GB**
compressed, not the 2.5 GB assumed.
