# P1.13 acquisition integrity incident and defect fix

**Dated** 2026-08-22 | **Design** P1.13-PROSPECTIVE-PUBLIC-MULTIGENUS-EXTERNAL-VALIDATION
**Classification** implementation defect in the acquisition path. Not a design amendment.
**Cohort effect** none. Membership, run accessions, target depth, seed, sampling algorithm,
assembler, tool panel, models and thresholds are all unchanged. Cohort sha256 prefix
`2e47d15b30a42181` is identical before and after.

## What happened

Phase 1 completed with 148 of 150 isolates md5-verified and refused to continue, exiting at the
`AD -eq 150` gate. Proceeding with 148 would have silently changed cohort membership, so the
abort was the correct behaviour and is recorded rather than suppressed.

Two files failed md5, in two different ways:

| Isolate | File | Bytes on disk | Bytes expected | Failure mode |
|---|---|---|---|---|
| SAMN48144070 | SRR36372753_1.fastq.gz | 344,064 | 261,467,249 | truncated |
| SAMN40123745 | SRR39132974_2.fastq.gz | 249,221,239 | 249,221,239 | **correct size, wrong content** |

The second case is the important one. The file was byte-for-byte the declared length and would
have passed any size or record-count check. Only the md5 detected it.

## Cause

Both transfers were interrupted when the runner was stopped for the pairing-validation pause. The
acquisition function retried with `curl -C -`, which resumes onto whatever partial file is already
present. Resuming onto a partial write appends from the wrong logical offset and can reconstruct a
file of exactly the right length carrying the wrong bytes. The md5 check then ran only once, after
the retry loop had already exhausted itself, so a corrupt file could never be recovered by retry:
every subsequent attempt resumed onto the same corruption.

ENA was not at fault. A HEAD request against both URLs returned exactly the expected content
lengths, so this was local transfer corruption, not a data-availability defect. Neither isolate
needed to leave the cohort.

## Fix

In `env/p113_run.sh`, acquisition now:

1. treats a present-but-md5-failing file as **corrupt, not partial**, and deletes it before
   refetching from byte zero;
2. never uses `-C -` resume on a file it has not validated;
3. re-checks md5 **inside** the retry loop, so a corrupt fetch is discarded and retried rather
   than being locked in by the first attempt.

The pre-fix script is retained as `env/p113_run.sh.pre_amend004`.

## Verification

After the fix, both files were refetched and Phase 1 completed **150/150 verified, 0 failed** in
77 seconds. No isolate was excluded, substituted or hand-picked.

## Lesson, consistent with the pairing amendment

A check that only compares sizes or counts does not establish content identity. This is the same
failure class the count-only pairing guard was replaced for: an artefact can carry the right shape
and the wrong data. Content digests are the authority at every stage of this pipeline.
